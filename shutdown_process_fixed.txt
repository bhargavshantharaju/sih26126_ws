SHUTDOWN AND PROCESS CLEANUP SOLUTION
======================================

## Problem Statement

Previous runtime tests encountered:
1. Duplicate/orphaned ROS processes after test completion
2. Gazebo simulator not fully terminating
3. SLAM nodes lingering after launch stop
4. Potential port conflicts on subsequent runs

## Root Causes Identified

1. **Launch Process Tree**: ros2 launch spawns many child processes
2. **Gazebo Cleanup**: gz sim can take 3-5 seconds to fully terminate
3. **Signal Propagation**: SIGTERM may not reach all descendants
4. **Bridge Persistence**: ros_gz_bridge nodes may outlive parent

## Solution Implemented

Created `cleanup_dristhi.sh` with staged shutdown:

### Stage 1: Graceful Launch Termination
- Send SIGTERM to known launch PID
- Wait up to 10 seconds for graceful shutdown
- This allows ROS nodes to cleanup subscriptions/publishers

### Stage 2: Additional Launch Processes
- Find any ros2 launch processes by pattern match
- Terminate with SIGTERM, wait 2 seconds
- Force kill (SIGKILL) any remaining

### Stage 3: Gazebo Simulator
- Identify gz sim processes
- Terminate with SIGTERM
- Wait 3 seconds (Gazebo needs time to cleanup physics/rendering)
- Force kill if still present

### Stage 4: ROS Bridges
- Immediately kill ros_gz_bridge with SIGKILL
- Bridges don't need graceful shutdown

### Stage 5: Specific Nodes
- Target known persistent nodes:
  * slam_toolbox
  * slam_activator  
  * slam_pose_adapter
  * ekf_filter_node
- Force kill with SIGKILL

### Stage 6: Verification
- Wait 2 seconds for cleanup to complete
- Count remaining processes
- Report success or list remaining processes

## Usage

### Direct Execution
```bash
./cleanup_dristhi.sh [launch_pid]
```

### From Test Scripts
```bash
source cleanup_dristhi.sh  # Load function
cleanup_dristhi $LAUNCH_PID
```

### Standalone
```bash
./cleanup_dristhi.sh  # Will find and terminate all DRISTHI processes
```

```bash

source cleanup_dristhi.sh

# Launch
ros2 launch ... &
LAUNCH_PID=$!

# Test...

# Cleanup
cleanup_dristhi $LAUNCH_PID
```

## Best Practices

### Do:
✅ Track launch PID for targeted cleanup
✅ Use graceful SIGTERM before SIGKILL
✅ Wait for Gazebo to cleanup (3-5 seconds)
✅ Verify cleanup succeeded before next launch
✅ Use pattern matching as fallback for orphans

### Don't:
❌ Use `pkill -9 ros2` (too broad, may kill other ROS work)
❌ Rely only on Ctrl+C (may not reach all descendants)
❌ Start new test immediately after kill (wait for cleanup)
❌ Use `killall` without specific patterns

## Process Ownership

All test-launched processes are:
- Owned by the user running the test script
- Children of the ros2 launch process
- Traceable via PID and process tree
- No root/sudo processes created

## Safety

The cleanup script:
- Only targets DRISTHI-specific patterns
- Checks process existence before kill
- Won't affect other ROS/Gazebo work
- Won't affect system processes
- Returns error code if cleanup incomplete
